Remove every Tailwind `emerald`/`green-*` class from the app and restyle the WhatsApp CTA using only the brand tokens already declared in `globals.css`.

<design_precedence_note>
Read this before comparing anything to `stitch-extracted/`.

`stitch-extracted/homepage/code.html` **itself** uses `bg-emerald-700 hover:bg-emerald-800` for its WhatsApp CTAs (lines 143, 605, 724) and `text-emerald-800` for the footer WhatsApp link (line 771). The implementation is a faithful port of that markup — the green is not implementation drift.

COLOR-01 is therefore a deliberate, requirement-mandated divergence from `code.html`, aligning instead to `DESIGN.md`, which declares exactly two accents (brick `#B24A2E` primary CTA, brass `#A87C3F` accent) plus oxblood `#4A1F1C` as the dark-surface token, and says "Do NOT use generic green environmental imagery".

Precedence for this phase: `REQUIREMENTS.md` > `DESIGN.md` > `code.html`. Do not restore green on the grounds that `code.html` has it.
</design_precedence_note>

Why oxblood rather than brick for the WhatsApp button: `DESIGN.md` reserves brick for the primary CTA, and `HeroSection.tsx:29-33` renders `<Button variant="primary">GET BULK PRICING</Button>` immediately beside `<WhatsAppButton>`. Making both brick would erase the distinction between them. Oxblood is the declared dark-surface token, keeps the pair legible against the `#F4EFE6` paper background, and stays inside the two-accent system.
</color_map>

<escape_map>
Only three literal escape sequences exist in this plan's files: `Header.tsx:23`, `MobileNav.tsx:25` and `MobileNav.tsx:53`, all `\u00b7`. Replace each with the real character `·` (U+00B7 MIDDLE DOT), typed directly into the source.

Why this is broken today: JSX text nodes are not JavaScript string literals, so the backslash in `Mirzapur, Uttar Pradesh \u00b7 Bulk Tableware` is emitted verbatim and the visitor reads the six characters `\u00b7`. Never convert it into a double-escaped `\\u00b7`.
</escape_map>
