<escape_map>
Replace each literal escape sequence with the character shown, typed directly into the source file. All files are UTF-8; write the glyph, not an HTML entity and not a `{'\u2192'}` expression.

| Literal in source | Character | Name |
|---|---|---|
| `\u00a9` | © | copyright sign |
| `\u00b0` | ° | degree sign |
| `\u00b7` | · | middle dot |
| `\u2013` | – | en dash |
| `\u2014` | — | em dash |
| `\u2019` | ’ | right single quotation mark (apostrophe) |
| `\u201C` | “ | left double quotation mark |
| `\u201D` | ” | right double quotation mark |
| `\u2022` | • | bullet |
| `\u2192` | → | rightwards arrow |
| `\u223c` | ∼ | tilde operator |
| `\u2709` | ✉ | envelope |
| `\u2713` | ✓ | check mark |
| `\u23F1` | ⏱ | stopwatch |
| `\u23F1\uFE0F` | ⏱️ | stopwatch + VS16 — replace the **pair** with the single emoji |
| `\u260e` | ☎ | black telephone |
| `\u267B\uFE0F` | ♻️ | recycling symbol + VS16 — replace the **pair** |
| `\uD83C\uDF74` | 🍴 | fork and knife — **surrogate pair**, replace both halves together |
| `\uD83D\uDCCD` | 📍 | round pushpin — surrogate pair |
| `\uD83D\uDCCF` | 📏 | straight ruler — surrogate pair |
| `\uD83D\uDCE6` | 📦 | package — surrogate pair |
| `\uD83D\uDE9A` | 🚚 | delivery truck — surrogate pair |

Two rules that a blind find-and-replace gets wrong:
1. **Surrogate pairs and variation selectors must be replaced as a unit.** `\uD83D\uDCCD` is one character (📍), not two. Replacing each half independently yields two lone surrogates and mojibake.
2. **Never produce a double-escaped result.** `\\u2192` is worse than the original.
</escape_map>

<why_it_breaks>
Three distinct situations exist in this codebase, and only the first two are actually broken. Inspect each occurrence before editing rather than assuming.

| Situation | Example in this repo | Rendered today | Action |
|---|---|---|---|
| JSX **text node** | `<span>\u2192</span>` — `MirzapurTransitSection.tsx:19` | literal `\u2192` — BROKEN | replace with `→` |
| JSX **attribute string** | `label="Ask for this size \u2192"` — `ProductCard.tsx:38` | literal `\u2192` — BROKEN | replace with `→` |
| JS **string / template literal** | `` caption={`${product.name} \u00b7 ${product.use}`} `` — `products/[slug]/page.tsx:42`; every entry in `src/content/*.ts` | correct `·` — already fine | replace anyway, for the clean grep gate; output is unchanged |

JSX attribute values are parsed like HTML attributes, not like JS strings — backslash escapes are not processed in either a JSX text node or a JSX attribute string. Inside a `{ }` expression container, or anywhere in a plain `.ts` module, normal JavaScript string-literal rules do apply, which is why `src/content/products.ts` and `src/content/site.ts` already render correctly.

Replacing a working escape with its literal character is behaviour-preserving: `'80\u2013100 GSM'` and `'80–100 GSM'` are the same string. Doing it everywhere lets plan 01-04 gate the entire repo with one grep instead of a grep plus an allow-list.
</why_it_breaks>
